# 行政管理工作手册

## 任务管理

### 任务状态变更

**待处理 → 已完成**

- **待处理**：发布任务后进行解决，出现变化则发布新任务。任务过程生成的信息放到文档里，不要把任务当成备忘录用。
- **已完成**：对处理完后的任务进行勾选完成。

### 任务清单流程

```
深思 → 整理 → 执行
```

**信息流：** 个人 → 角色 → 部门 → 公司 → 联盟 → 社区

## 深思工作法

### 记录

在工作遇到问题时记录，突然冒出想法时记录。

### 浅层分类

使用 AI 辅助整理分类原始信息。提示词示例：`分类整理原始信息，保留原话。`

豆包在此场景下比 DeepSeek 和 Kimi 更适合，不会过多延伸。

### 深层分类

区分**工作档案**（成果/信息的沉淀载体）和**工作手册**（方法/实践的执行指南）。

提示词示例：
```
区分工作档案和工作手册，如果区分不了放在未分类，保留原文。
```

## 消息渠道

### 群组分类

| 类型 | 用途 | 示例 |
|---|---|---|
| **业务群** | 对接内外部，如新单信息 | 量潮数据、量潮课堂 |
| **职能群** | 协调内部资源 | 项目管理、人力资源、财务管理 |

**信息流转：** 业务群分解职能后信息流转到职能群，职能群汇总信息到业务群对外流转。

### 精炼消息记录流程

1. 使用飞书消息导出到文档功能，导出到一个临时文档
2. AI 辅助梳理（如腾讯元宝）
3. 加工整理到正式文档
4. 邀请读者评审并定稿

## 审批管理

### 审批权分配原则

**尽可能去中心化**，由掌握标准的相关职能的职级最低层的事务官建立和维护审批流程。

例如，财务相关的由财务直接负责和审批——只要财务掌握标准就值得信任。如果财务自己有问题，通过既定协商方式事后修复。

这样系统可以保持敏捷的同时快速修复，初级事务官也可以在这样的模式下快速学习审批权如何维护。

> 设计者注：审批去中心化的核心逻辑是"谁掌握标准谁审批"。把审批权放在最了解情况的人手里，而不是层层上报。低职级事务官能审批不是因为权力大，而是因为他们掌握标准。出错不可怕，有修复机制就行——这比所有事情都集中到高层审批要高效得多。

## 附录：行政管理检查清单

验收标准：任务状态应已及时更新，消息记录应已完成精炼和归档，审批流程应已按去中心化原则配置，深思工作法的记录应已分类整理。

## 手册使用建议

1. 任务是临时动作，文档是长期资产——不要把任务当成备忘录用。
2. 去中心化审批的核心是"标准清晰"，标准模糊的地方不适合下放审批权。
3. 手册不替代章程：正式行政制度以章程为准。
