# 课程管理工作手册

## 议事型课堂

议事型课堂是以"议事规则"为核心的教学模式——学生像议员一样提案、附议、辩论、决议，在真实问题的讨论中完成知识建构。

### 教研流程

#### 体验课三阶段

| 阶段 | 范围 | 目标 |
|---|---|---|
| **内测（Alpha）** | 内部团队 | 获得内部认可，建立获客信心 |
| **公测（Beta）** | 学生代表 | 获得客户认可 |
| **正式体验** | 意向客户 | 获得市场认可 |

#### 内测执行步骤

1. 课程部推出体验课
2. 组织 C 端工作组体验
3. 工作组反馈不满意的地方
4. 课程部针对问题思考，在群里分享解决思路，确认后修改
5. 一轮修改后重复上述内容

#### 正式体验执行要点

- 针对愿意下单的客户，询问下单原因，形成经验积累
- 列出几个无下单意愿的选项，向未产生下单意愿的客户询问，获取具体原因

> 设计者注：体验课的设计逻辑参考了软件测试的思路。内测找内部人找茬——只管提问题，不用给解法。公测让学生代表验证。正式体验才面向市场。每个阶段的目标不同，不要跳过。内部没通过的课，不要推向外部。

### 教学流程

完整流程：**教研 → 内测体验 → 公测体验 → 正式体验 → 正式授课**

每个环节需要明确产出标准。体验课的目的是验证课程设计是否有效，而不是追求完美——短而精，快速迭代。

## 评估议事型课堂

### 责任人

- **助教**：产生评估报告
- **教师与督导团队**：评估

### 评估流程

1. 导出上课用的资料作为素材
2. 和 AI 讨论明确评估此类课堂效果的标准
3. 结合二者请 AI 评估形成报告，提交到当堂课程的复盘之前

### 评估维度

| 维度 | 关键指标 |
|---|---|
| **个体参与与认知发展** | 从"发言"到"思维跃迁"的证据 |
| **协作过程与系统运行** | "三权"（学生/教师/企业）的有机互动 |
| **成果产出与价值创造** | 决议的质量——结构化、分析深度、价值判断 |
| **生态健康与可持续性** | 心理安全、趣味性、文化迁移 |

### 核心评估标准

**能否持续地、高质量地复现"从混乱的附议到深刻的决议"这一知识创造过程。**

- 基础参与：参与广度达标（区分"简单枚举"与"深度分析"）
- 深度参与：识别并奖励系统思维和批判性洞察
- 认知发展轨迹：追踪在问题认知深度上的演进
- 老师/引导者价值：介入的时机、提问的精准度、信息增值度

> 设计者注：议事型课堂的评估不是传统的"考试分数"，而是观察"知识创造过程"的质量。好的课堂应该能看到学生从举例子到分析原因再到提出判断的思维跃迁。老师的价值不在于讲了多久，而在于何时介入、问了什么问题。评估报告不是给行政看的，是给下一轮教研用的。

## 附录：课程管理检查清单

- [ ] 体验课处在哪个阶段（内测/公测/正式）？
- [ ] 内测反馈是否已收集并迭代？
- [ ] 正式体验的下单/未下单原因是否已记录？
- [ ] 课堂评估报告是否已完成？
- [ ] 评估是否覆盖了四个维度？

## 手册使用建议

1. 教研和教学是迭代关系——每次授课的评估结果都是下次教研的输入。
2. 评估聚焦"知识创造过程"而非知识点记忆。
3. 手册不替代章程：正式课程制度以章程为准。
