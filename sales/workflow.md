# 销售流程工作手册

## 核心理念

销售流程的核心是**调研式推销**——先了解再推销，先给价值再要承诺。不是硬推产品，而是帮对方发现自己需要什么。

## 标准流程

### 第一步：客户画像与筛选

**不要广撒网，要精准筛选。**

| 维度 | 标准 | 排除条件 |
|------|------|---------|
| 身份 | 个人开发者、编程学习者、技术爱好者 | 企业客户（走商务流程） |
| 需求信号 | 主动提问"怎么学编程"、"怎么转行"等 | 仅围观无明确需求 |
| 付费能力 | 有稳定收入或明确学习预算 | 学生无预算（可走公益渠道） |
| 决策链 | 自己能决定是否付费 | 需他人批准 |

**操作：** 每天浏览技术社区、社交媒体、群聊，把符合上述标准的潜在用户记录到客户跟进表。

### 第二步：首次触达

**遵循"共鸣 + 价值 + 留白"公式。** 不要一上来就发广告。

```
共鸣：发现你在学XX，我当时也卡在这块……
价值：后来我用了一个方法/一份资料，效率高了很多
留白：如果你需要，我可以发你看看
```

**验收标准：**
- [ ] 每条触达消息都包含共鸣点
- [ ] 每条都提供了免费价值
- [ ] 没有直接发购买链接

### 第三步：需求确认

当对方回应后，进入需求确认阶段。目标是**搞清楚对方真正的痛点**。

```
「你现在主要卡在哪个环节？」
「你希望达到什么效果？」
「之前试过什么方法？效果怎么样？」
```

**不要做的：**
- 不要问"你预算多少"（过早问价会吓跑）
- 不要直接报价（先建立价值认知再报价）
- 不要贬低竞品（显得不专业）

### 第四步：价值展示

确认需求后，针对性地展示解决方案。**用量潮课堂的实战项目案例说话。**

```
「我们有个大数据实践课，就是做真实项目的。
  浙江理工大学计算机系在用，学生跑完直接能写简历。
  我觉得特别适合你现在的情况。」
```

**素材来源：** 微信公众号「量潮科技」、产品介绍页、学员案例

### 第五步：异议处理

常见异议及回应：

**太贵了**：先确认是预算不够还是觉得不值。预算不够→推荐轻量方案；觉得不值→回到价值展示

**我再想想**：确认具体犹豫点。不要施压，给一个低门槛行动（如先试听一节）

**没时间**：确认时间安排的瓶颈，推荐碎片化学习方案

**我自己学也行**：对比自学vs系统学习的效率差异，用真实案例说明

详细话术参见 `scripts.md`。

### 第六步：促成转化

**不逼单，给明确的下步行动。**

```
「要不这样，你先体验一下课程的内容，觉得合适再决定。」
「本周有折扣名额，如果你感兴趣我可以帮你留一个。」
```

**确认转化后——**
1. 引导用户完成支付/报名
2. 通知教务团队安排课程
3. 更新客户跟进表状态为"已转化"

### 第七步：跟进与服务

**销售不结束于成交，结束于用户拿到结果。**

- 转化后 3 天内：确认用户顺利入学
- 转化后 1 周：了解学习进度
- 课程中期：收集反馈，解决困难
- 课程结束后：邀请写评价、推荐朋友

## 全流程检查清单

- [ ] 客户画像是否精准？
- [ ] 首次触达是否提供了价值？
- [ ] 需求确认是否问清楚了痛点？
- [ ] 价值展示是否针对痛点？
- [ ] 异议处理是否留有余地？
- [ ] 促成转化是否给了明确行动？
- [ ] 跟进服务是否到位？
