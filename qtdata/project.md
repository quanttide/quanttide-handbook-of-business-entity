# 项目交付标准流程与模板

## 一、项目管理标准作业程序（SOP）

### 需求阶段

1. 客户提需求 → 回复：“收到，我将根据需求整理一份项目策划书，预计明天下午前发您确认”
2. 撰写项目策划书，发客户确认：“策划书已发您邮箱，请重点确认交付范围和时间规划，没问题的话我们进入报价流程”
3. 根据客户反馈修改策划书，直至客户确认
4. 客户确认后，拿策划书找技术评估工时：“这个需求工时预估是多少？有没有技术卡点？大概需要几个人天？”

### 报价阶段

1. 根据技术评估的人天，找商务出报价单（含首尾款比例）
2. 报价单发客户确认：“您好，这是报价单，您看看是否接受”
3. 如客户嫌贵或要求降价，执行降价评估子流程：
   - 回复客户：“收到，我理解预算方面的考虑。我这边内部重新评估一下需求范围，看看是否有降本方案可以给您选择，稍后给您回复”
   - 找技术评估：“在不影响核心交付的前提下，有哪些功能模块可以先不做或者简化做？数据采集范围能不能缩小？每个调整方案大概能省多少人天？”
   - 将降本方案整理发给商务，由商务重新出报价单
   - 新报价单发给客户确认。客户接受则进入合同流程；仍不接受则礼貌收尾，留有余地

### 合同与启动阶段

1. 客户接受报价后，找商务出合同，发客户确认：“您好，这是我司撰写的合同，您看看是否接受”
2. 客户确认合同后，走飞书审批流程盖章，盖章合同发客户
3. 提醒客户付首款：“合同已盖章发出，确认无误后请支付首款，款到后我们立即安排技术启动”
4. 确认首款到账后，通知技术开工：“客户已付首款，请及时开始项目”，内部建立进度文档

### 开发与跟进阶段

1. 开发过程中，每周主动找技术确认进度：“本周完成了什么？下周计划做什么？有没有卡点？预计交付时间有变化吗？”
2. 根据项目周期，定期（每周或每两周）向客户同步进度

### 交付与验收阶段

1. 技术完成开发后，将交付物通过邮箱发给客户：“项目交付物已发至您的邮箱，注意查收，如有问题随时沟通”
2. 交付邮件附温馨提示：“本次交付物请您及时下载并妥善保存。根据公司数据管理规则，我们为客户保留项目交付物的期限为交付后XX天，超期后原始数据将自动清理，届时如需重新获取可能产生额外工作量费用。感谢您的理解与配合。”
3. 客户确认没问题后，向客户要尾款：“麻烦确认一下，交付物是否还有需要调整的地方？如果没问题，我这边就发您尾款支付通知”
4. 如需开发票，同步联系财务处理
5. 客户对交付物有疑问或不确认时，及时反馈技术修改，重复14-16直至项目结束

### 收尾阶段

1. 项目结束后，整理所有项目文档、沟通记录、代码资产，归档至公司知识库，方便后续类似项目复用
2. 撰写项目复盘，记录核心风险、技术难点、解决方案和经验教训

## 三、客户沟通参考话术

### 初次对接

- “您好，我是量潮科技的PM XXX，后续本项目由我跟进对接。有任何问题随时在群里@我，我会及时响应。”

### 报价协商——客户嫌贵/要求降价

- 先稳住客户：“收到，我理解预算方面的考虑。我这边内部重新评估一下需求范围，看看是否有降本方案可以给您选择。稍后给您回复。”
- 备选（如客户追问降幅）：“具体降幅需要和技术评估后才能确认，我尽快，今天之内给您一个方向性反馈。”

### 报价协商——客户对新报价仍不满意

- 客户说“还是有点贵，能再降点吗？”→ “收到，我再内部评估一下是否还有进一步精简的空间。稍后回复您。”
- 客户说“还是太贵了，我们暂时不做了”→ “好的，理解。后续如果有类似需求或预算调整，随时可以再联系我们。祝项目顺利！”
- 客户说“能不能在原方案基础上直接打折，不做功能删减？”→ “不好意思，报价是根据技术评估的工作量核算的，直接打折会影响交付质量。如果预算确实有限，建议还是从需求范围上做减法，这样项目也能顺利落地。您看是否考虑我们提供的降本方案？”

### 进度汇报

- 正常推进时：“X老师您好，跟您同步一下本周进度。目前已完成XX，进行中XX，预计XX时间交付。暂无需要您配合的事项，有问题随时沟通。”

### 交付验收

- “X老师您好，项目交付物已发至您的邮箱，注意查收，如有问题随时沟通。本次交付物请您及时下载并妥善保存。根据公司数据管理规则，我们为客户保留项目交付物的期限为交付后XX天，超期后原始数据将自动清理，届时如需重新获取可能产生额外工作量费用。感谢您的理解与配合。”
- 客户确认后要尾款：“麻烦确认一下，交付物是否还有需要调整的地方？如果没问题，我这边就发您尾款支付通知。如需开发票请同步提供开票资料。”

### 客户不确认交付物

- “好的，问题会尽快向开发反馈，请您耐心等待，如有问题随时沟通。”
