
# 数据工程
我们的数据工程体系非常庞大复杂，不同类型的项目，比如爬虫、文本标注、清洗精炼，都有各自特定的一套规范，每一类规范下面还有子规范，例如问卷数据的清洗本身就构成一类规范。因此规范的层级就分很多层：首先需要一个通用的数据工程框架，然后是针对每一类项目的特定框架，每一类项目之下还要有子类的特定框架。
在编制手册的时候，往往需要从某一个具体项目出发，将经验总结到对应的子类里，再通过子类经验的持续积累，不断总结出更加适用于一般情况的规律，最终形成通用的框架。而在使用手册的时候，需要从这一通用的框架出发。面对新项目时，先用通用框架对其进行界定，缩小到某一子类；若该子类已有相关经验，就能通过手册关联到内部具体实践，明确如何操作。所以，无论是编制还是使用标准化流程，首要工作都是进行大量分类，涵盖任务类型、难度等级等方面。
整个体系在搭建时必须具备很强的归纳性。其核心逻辑主要基于两个视角：一是交付视角，聚焦以数据为中心的交付物积累，关键是明确定义相关概念；二是流程视角，可称为DataOps或其他，涵盖从项目启动到交付的完整动态流水线，包括各环节任务、人员协作与流程管控。手册的基本框架应由这两部分构成。除此以外，其余内容均需在各子类下具体展开，且每个子类都必须具备清晰的定义。
