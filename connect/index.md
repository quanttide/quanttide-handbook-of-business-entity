# 沟通管理工作手册


## 沟通渠道与平台

| 渠道 | 用途 |
|------|------|
| 消息 | 日常协同、快速确认 |
| 邮件 | 正式沟通、外部对接 |
| 会议 | 复杂讨论、决策对齐 |

**沟通流程：** 外部 → 内部 → 外部（信息从外部流入，内部消化后，再输出到外部）。

## 沟通基本原则

动手写信息前先判断两个问题：

1. **对象是谁？** 内部同事还是外部人员？
2. **说什么？** 日常确认、正式决策、还是复杂讨论？

第一个问题决定用哪个模板，第二个问题决定用哪个渠道。

| 对象 | 模板 | 渠道 |
|------|------|------|
| 内部 | 精简优先：背景一句话、任务具体、附上材料 | 日常走消息，正式走邮件 |
| 外部 | 友好优先：完整上下文、正文定结论、附件仅补充 | 正式走邮件，复杂走会议 |

**经验提醒：** 不要用消息渠道传递正式决策。在群里说"那就这么定了"没有书面记录，事后谁也说不清。正式决策走邮件或备忘。

## 内部沟通

内部沟通发生于共享组织上下文的环境。发送方与接收方默认具备共同的业务背景知识。

### 核心策略：精简优先，带到即可

- **精简表达**：基于双方共同上下文进行表达，不重复对方已知的信息。
- **附件预期**：发送方将材料附上并指明查阅位置即可。接收方有义务在回应前查阅已附上的材料。
- **流程从简**：减少不必要的审批节点和信息中转。同部门内直线传递，跨部门指定单一对接人汇总。

### 内部备忘模板

```
【背景】（一句话说明）
【任务】（具体动作）
【附件】（相关材料链接）
【截止】（时间节点）
【反馈】（结论发给谁）
```

### 使用要点

- 上下文省略：默认双方知道项目背景，不必从头解释。
- 附件即正文：附上材料即可，不必在正文中完整引用。
- 直接收尾：写清楚"XX前回复"或"自行推进"，不需要多余客套。

## 外部沟通

外部沟通发生于缺乏共享组织上下文的环境。发送方须承担信息适配的主要责任。

### 核心策略：友好优先，正文定结论

- **零起点说明**：展开所有内部术语和简称。不得假设对方了解公司业务背景。
- **正文完整**：核心结论和关键依据必须在正文中直接呈现，不得仅以附件方式传递。
- **附件辅助**：附件仅为补充佐证，不得假设对方会阅读附件。
- **预留时间**：外部沟通节奏不同，给对方留出合理的回应窗口。

### 外部沟通保障

面向外部人员的沟通，还应满足以下要求：

- 文档具备完整上下文说明，使新接手的人员也能理解来龙去脉。
- 重要事项以邮件或书面备忘确认，不得仅以消息渠道传递。
- 预留充分的接收与反馈时间。

### 外部沟通模板（备忘/邮件）

```
【背景】（完整上下文）
【核心事项】（关键结论写在正文）
【期望行动】（希望对方做什么）
【附件】（补充佐证）
【反馈路径】（对接人及渠道）
```

### 使用要点

- 零起点：把"请走 PR 流程"改成"请通过项目评审流程提交需求"。
- 正文定结论：不写"详见附件"，核心判断放在正文。
